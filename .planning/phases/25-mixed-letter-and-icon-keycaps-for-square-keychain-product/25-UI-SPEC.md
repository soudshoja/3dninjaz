# Phase 25 — UI Design Contract

> Visual and interaction contract for the mixed letter + icon keycap feature on the SQUARE keychain PDP and its admin/production surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **This is a feature EXTENSION, not a new page.** Every surface below extends an existing Phase 19 component and MUST stay visually indistinguishable from the current keychain experience except where the new capability (icon slots) demands new affordances. Do NOT introduce a new page shell, new brand colours, or a marketing treatment. Reuse the Claymorphism system already established in `configurable-product-view.tsx` / `configurator-form.tsx`.

The phase touches five UI surfaces. Each row names the existing file it extends and the single new job it gains.

## Spacing Scale

Declared 8-point scale (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, chip inner padding, slot-tile inner gap |
| sm | 8px | Compact element spacing, gap between slot tiles |
| md | 16px | Default element spacing, card inner padding step |
| lg | 24px | Section padding, gap between field groups (`gap-6`) |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Exceptions (inherited from the established Claymorphism system — do NOT "fix" these; new code must match the surrounding component):**
- Claymorphism borders/offsets use 2px / 2.5px / 3px hairlines and 6px / 10px / 14px card radii-adjacent offsets already present in `configurable-product-view.tsx`. New slot tiles reuse these exact values.
- Touch targets: every interactive slot tile, icon-grid cell, and "add" button is **≥ 48px** (mobile-first, matches existing colour chips at 48px disc / 52px hit area and inputs at `minHeight: 56`).
- Slot tile size: **56px × 56px** (matches the input `minHeight` rhythm and the preview cube max of 56px). Icon-grid cell: **≥ 64px** square so the 512px icon render reads clearly.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (Chakra Petch) | 1.5 |
| Label | 14px | 700, uppercase, tracking-wide | 1.2 |
| Heading (section) | 18px (`text-lg`) | 700, uppercase, tracking-wide (Russo One via `font-[var(--font-heading)]`) | 1.2 |
| Display (H1 / price / glyph) | 24–36px responsive (H1); price pill `text-2xl`; keycap glyph `clamp(13px…26px)` | 800–900 (extra-bold / black — established Claymorphism accent weight) | 1.1–1.2 |

Notes:
- Two structural weights govern text: **regular 400** (body) and **bold 700** (labels/headings). The **800/900 extra-bold/black** tier is a pre-existing, deliberate Claymorphism *display* accent (price pill, CTA, keycap glyph, "Live" tag) — it is an established system feature, not new for this phase. New copy reuses these tiers as-is; do not introduce a fourth weight.
- Small helper/hint text: 12px (`text-xs`) at weight 400–600, colour `#6b7280` — matches every existing field hint.
- Slot-count counter uses `tabular-nums` (matches the existing `{value.length}/{maxLen}` character badge).

Established 60 / 30 / 10 split (unchanged — see `src/lib/brand.ts`):

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F7FAF4` (BRAND.cream) page bg + `#ffffff` card surfaces | Page background, all card interiors, slot-tile default fill |
| Secondary (30%) | `#ffffff` white cards with `BRAND.ink` @ 10–18% alpha borders/shadows | Cards, dialog surfaces, slot rail, icon grid backdrop |
| Accent (10%) | `#25D366` (green), `#1877F2` (blue), `#7360F2` (purple) | See reserved-for list below |

**Accent reserved for (explicit — never "all interactive elements"):**
- **Green `#25D366`** — the primary "Add to Bag" CTA, the *selected/filled* state of a slot or icon (selected ring + checkmark), the "Live" preview tag, and the resolved price pill. (Matches existing colour-chip selected ring and CTA.)
- **Blue `#1877F2`** — active/focused text input border + focus ring, letter-slot accent dot, the "Add letter" affordance, section accent bars on the PDP.
- **Purple `#7360F2`** — colour-field accent dot, the "Add icon" affordance and icon-slot accent dot (so letter vs icon slots are visually distinguishable at a glance without relying on shape alone), breadcrumb link, "Material & Craft" section bar, and the admin production Icon-segment accent stripe.

Icon-slot fill colour on the preview shell is **fixed white `#FFFFFF`** (the physical keycap base — D-04/`<specifics>`); the icon's own baked accent colours come from the committed WebP render, never from customer colour fields.

## Interaction Contract (new behaviour this phase introduces)

The template's fixed sections don't capture the novel interactions, so they are specified here prescriptively for the executor.

### S1 — Slot-sequence builder (PDP)
- Renders a single horizontal, wrapping **slot rail** of 56×56 tiles in sequence order, followed by two "add" affordances: **`+ Letter`** (blue) and **`+ Icon`** (purple).
- **Letter slot tile:** shows the typed uppercase glyph on a white tile with a blue accent border; tapping it focuses an inline single-char edit (or the shared text input — executor's choice, but typing must feel identical to today's name field: uppercase-forced, `allowedChars`-filtered). Blue accent dot / left stripe marks it as a letter.
- **Icon slot tile:** shows the chosen icon's WebP thumbnail on a white tile with a purple accent border; tapping it re-opens the icon picker (S2) to change it. Purple accent marks it as an icon. **No Base/Clicker/Letter control appears on or near an icon slot** (D-04).
- **Shared counter** renders as `N/maxSlots` in `tabular-nums` (reuse the existing character-badge style). When `N === maxSlots`, both `+ Letter` and `+ Icon` disable and a "Maximum reached" chip appears (same rose treatment as the existing text field). Slot count = letters + icons combined (D-02).
- **Remove** a slot via a small `×` on hover/focus of the tile (top-right, ≥ 24px hit target expanded to 44px on touch). Removal is instant, non-destructive to other slots; no confirmation dialog (low-stakes, reversible by re-adding).
- Empty state (zero slots): the rail shows a single dashed 56px placeholder tile plus both add buttons and the empty-state copy (see Copywriting).
- Reordering is **out of scope for v1** — slots append in tap order; to reorder, the customer removes and re-adds. (Do not build drag-and-drop this phase.)

### S2 — Icon picker (PDP)
- Opens as a **popover/sheet on mobile, popover on desktop** anchored to the tapped icon slot or the `+ Icon` button. (Reuse the project's existing dialog/popover primitive; do not hand-roll a modal.)
- Content: a responsive **grid** (≥ 64px square cells, `auto-fill minmax(64px, 1fr)`), one cell per icon in `allowedIconIds` order. Each cell = the WebP thumbnail + a 12px label under it (truncated with ellipsis, full name in `title`).
- Tapping a cell fills the slot and closes the picker. The currently-selected icon (when editing an existing slot) shows the green selected ring + checkmark (reuse colour-chip selected treatment).
- The 3 franchise-logo groups are shown exactly like every other icon — **no badge, no warning, no grouping by IP** (D-08). Do not add any "licensed" or "trademark" affordance.
- If `allowedIconIds` is empty (admin configured none), the `+ Icon` affordance is **hidden entirely** and the builder behaves as letter-only (graceful degrade).

### S3 — Live preview (mixed strip)
- Extend `KeychainPreview` to accept a render model of ordered slots (letters keep today's 3-layer CSS cube with `baseHex/clickerHex/letterHex`; icons render the WebP `<img>` centered on the fixed white shell cube, same cube geometry/shadows).
- **Pixel-parity guarantee:** when the sequence is all-letters, the rendered strip MUST be byte-for-byte identical to today's output (same clamp sizing, same ring tab on cube #1, same shadows). Icon cubes reuse the identical shell/border/shadow — only the inner content differs (image vs glyph).
- Icon `<img>` sits within the inset face area with `object-fit: contain`, `≤ 100%` of the inset, `alt=""` (decorative — the slot's meaning is conveyed by the builder, and the container already has `role="img"` + `aria-label`).
- The mobile sticky preview strip and the hero preview both consume the same slot model (they already share state today) — update both call sites.

### S4 — Admin icon-library allow-list
- Reached from the `keycapseq` field editor inside `config-field-modal.tsx`. Presents a **"Select icons"** button that opens `IconPickerDialog` (adapted from `ColourPickerDialog`: shadcn Dialog, `max-w-[720px]`, single fetch of the static catalog on open, client-side name filter, multi-select staged in a `Set<string>`, pluralised footer counter, disabled-when-zero confirm CTA).
- Selected icons render back in the field editor as a compact thumbnail strip with a count Badge (mirrors how attached colours render). Because the catalog is static, this is read-from-catalog + allow-list only — no upload, no CRUD.
- Reuse the existing native-checkbox-with-brand-accent pattern from `ColourPickerDialog` (no new Checkbox primitive).

### S5 — Admin production icon batch
- Add a fourth `Seg` / board section labelled **"Icons"** with a **purple** accent stripe (distinct from Base/Clicker+Letter green/blue) inside the existing Square board only (icons are square-only, D-01).
- Each icon batch card mirrors the existing base/clicker card shape (`keychain-batches.tsx`): left accent stripe, image + label (from `KEYCAP_ICONS`), a total-count Badge (`Boxes` chrome icon + `tabular-nums`), and a printed **tick** checkbox (reuse the existing 20px check-box control and progress bar). **No colour chips** on icon cards (colours are fixed).
- Assembly readiness card gains a third condition line: assemblable only when all letter parts AND all icon parts are ticked.

- Never surface "franchise", "licensed", "trademark", or any IP language anywhere (D-08).
- Retain "bag" as the cart vocabulary (CLAUDE.md cart-vocabulary note) — never "cart".

## Accessibility & Responsive

- All add/slot/icon-grid controls ≥ 48px touch target (44px minimum honored on the remove `×`).
- Slot rail wraps (no horizontal page scroll on mobile); icon grid scrolls inside its own container if it overflows the popover.
- Letter vs icon distinction never relies on colour alone: letter tiles carry a glyph, icon tiles carry an image, and each has a distinct accent dot + `aria-label` ("Letter S" / "Icon: Alien").
- Preview container keeps `role="img"` + descriptive `aria-label` summarising the sequence (e.g. "Preview: S, O, Alien, Skull").
- Theme: storefront is single-theme (cream/ink, matches existing PDP — no dark-mode variant this phase).
