    `export async function advanceGeneration(id: string)`: load row by id (return null if missing); switch on row.status — statuses NOT in MESHY_ACTIVE_STATUSES return the row unchanged (no-op). Active branches:

    2. **"revising"** — load newest revision: select from meshyRevisions where generationId = id orderBy desc(createdAt) limit 1. Poll by revision.endpointUsed: "retexture" -> getRetextureTask(revision.meshyTaskId); "regenerate" -> getImageTo3DTask(revision.meshyTaskId).
       - SUCCEEDED -> persistModelAssets (same download-first rule) then update generation { meshyTaskId: revision.meshyTaskId (the revision task becomes the CURRENT model task — 21-CONTEXT "meshyTaskId = current model's task"), localModelFiles, localThumbnailPath, status: "awaiting_review", modelReadyAt: new Date(), printabilityStatus: null, printabilityReport: null (stale analysis invalidated by new model), updatedAt }.
       - FAILED + endpointUsed "retexture" -> previous model is intact: update { status: "awaiting_review", taskErrorType, taskErrorMessage, updatedAt } (admin sees the error banner but keeps the old model).
       - FAILED + endpointUsed "regenerate" -> update { status: "failed", taskErrorType, taskErrorMessage, updatedAt }.
    3. **"analyzing"** — getPrintabilityAnalysis(row.meshyAnalyzeTaskId):
       - SUCCEEDED -> update { printabilityStatus: (task.status-field from PrintabilityResult: "healthy"|"warning"|"error", else "unknown"), printabilityReport: JSON.stringify({ is_watertight, volume, non_manifold_edge_count, degenerate_face_count, hole_count } picking ONLY fields Meshy actually returned — UI must not fabricate zeros), status: "ready", updatedAt }.
       - FAILED -> analyze is free + non-critical: update { printabilityStatus: "unknown", status: "ready", updatedAt } + console.warn — do NOT fail the generation.
    4. **"repairing"** — getRepairTask(row.meshyRepairTaskId):
       - SUCCEEDED -> download returned model_urls entries (repair output format mirrors input — write whichever of glb/stl came back, merging over existing localModelFiles), then chain a FREE re-analyze: analyzePrintability({ input_task_id: row.meshyRepairTaskId }) -> update { localModelFiles: merged, meshyAnalyzeTaskId: newAnalyzeId, status: "analyzing", updatedAt }. (Free call, keeps printabilityStatus honest post-repair; repair itself only ever fires from the explicit-click action.)
       - FAILED -> repaired nothing but the model still exists: update { status: "ready", taskErrorType, taskErrorMessage, updatedAt }.
    5. **"processing_multicolor"** — getMultiColorTask(row.meshyMulticolorTaskId):
       - SUCCEEDED -> downloadMeshyAsset(model_urls["3mf"], id, "model.3mf") -> merge into localModelFiles.threeMf -> update { isMultiColor: true, status: "ready", updatedAt }. Same test-mode tolerance as branch 1.
       - FAILED -> update { status: "ready", taskErrorType, taskErrorMessage, updatedAt }.

    `async function persistModelAssets(generationId, task)`: downloads task.thumbnail_url -> "thumb.png", task.model_urls?.glb -> "model.glb", task.model_urls?.stl -> "model.stl" via downloadMeshyAsset; returns { ok: boolean; files: LocalModelFiles; thumbPath?: string } where ok = all attempted downloads succeeded. Merge semantics: caller merges over existing parseLocalModelFiles(row.localModelFiles).

    All updates write JSON columns via JSON.stringify (MariaDB LONGTEXT — PATTERNS §8.3). Wrap each Meshy GET in try/catch: on MeshyHttpError log `[meshy-pipeline]` warn and return row unchanged (transient network must never wedge a row into failed).
