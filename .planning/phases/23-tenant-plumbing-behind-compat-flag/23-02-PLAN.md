<objective>
Ship the tenant-aware cache-tag helpers standalone, with NO existing consumer — Phase 24 wires them during the singleton sweep. Landing them first makes partial prefixing impossible: there is one and only one way to build a cache tag or key for a tenant, and it is always namespaced `t:<tenantId>:`.

Purpose: One Node process serves every tenant, so Next.js's `unstable_cache`/`revalidateTag` and any module memoization are process-global (PITFALLS.md Pitfall 8). An unprefixed tag is a cross-tenant cache leak — tenant A's storefront rendering tenant B's cached settings (first-request-wins poisoning). PITFALLS.md technical-debt table is explicit: partial prefixing is indistinguishable from none — "all or nothing."

Output: `src/lib/tenant/cache-tags.ts` + co-located vitest tests.
</objective>
