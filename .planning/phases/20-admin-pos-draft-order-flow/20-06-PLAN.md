    - First await is token validation (NOT requireAdmin per D-25):
      1. SELECT paymentLinks WHERE token = ?
      2. If row missing OR `link.usedAt !== null` OR `link.expiresAt < now()` → return `{ok:false, error:'Invalid or expired link'}` and DO NOT proceed.
      3. SELECT orders WHERE id = link.orderId
      4. If order missing OR `order.status !== 'awaiting_customer'` → return `{ok:false, error:'Order not accepting payment proofs'}` and DO NOT proceed.
    - After validation passes:
      5. Extract `file` from formData.
      6. Call `writePaymentProof(orderId, file)` — relies on the helper's MIME + size validation (so this surface inherits the 10 MB + allowlist caps per D-10).
      7. On writer error → return its error verbatim (no DB write).
      8. Insert payment_proofs row: `uploaded_by='customer'`, `uploaded_by_user_id=null`, `status='pending'`, snapshot imageUrl/thumbnailUrl/mimeType/sizeBytes from writer result.
      9. `assertValidTransition(order.status, 'awaiting_payment_review')` then `db.update(orders).set({status:'awaiting_payment_review', paymentMethod:'bank_transfer'}).where(...)`.
      10. `revalidatePath('/payment-links/[token]','page')` so the page re-renders into the "being reviewed" state.
      11. Return `{ok:true, proofId}`.
    - paymentLinks.usedAt is NEVER touched here — only set when order reaches `paid`.
    - All steps wrapped in `db.transaction` so partial failure doesn't leave the file on disk with no DB row (acceptable — file orphan is a known minor leak; transaction primarily protects DB consistency).
  </behavior>
