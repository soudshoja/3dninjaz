THE CATEGORY-A TRANSFORM (identical for every file in this plan). Analog: src/actions/admin-coupons.ts.
```typescript
// BEFORE
"use server";
import { db } from "@/lib/db";                         // ← DELETE this line
import { coupons } from "@/lib/db/schema";             // ← KEEP (schema import)
import { requireAdmin } from "@/lib/auth-helpers";

}

// AFTER
"use server";
import { coupons } from "@/lib/db/schema";             // schema import unchanged
import { requireAdmin } from "@/lib/auth-helpers";
export async function listCoupons() {
  const { db } = await requireAdmin();                  // ← capture tenant db (still FIRST await)
  const rows = await db.select().from(coupons)...       // ← now tenant-scoped; single-mode identical
}
```
RULES (apply to EVERY export in EVERY file):
1. Delete `import { db } from "@/lib/db"`. Keep all `@/lib/db/schema` imports.
2. Every `await requireAdmin();` (discard) → `const { db } = await requireAdmin();`. It MUST stay the first await.
3. If an export already captured the guard (`const session = await requireAdmin()`), change to `const { db, ...` and keep any `session`/`user` usage off the returned object (the return is backward-compatible `{ session, user, tenant, db }`).
4. Do NOT change db-using logic, transactions, or manual-hydration.
5. `revalidateTag(CATEGORY_TREE_TAG)` (if present) → `const { tenant } = await requireAdmin(); revalidateTag(tenantTag(tenant.id, CATEGORY_TREE_TAG));` (import tenantTag from @/lib/tenant/cache-tags). `revalidatePath(...)` stays unchanged (path revalidation is tenant-agnostic in single mode; per-tenant path busting is a Phase-25 concern — leave as-is).
6. `publicUrl(path)` calls (e.g. admin-manual-orders payment links, admin-payment-proofs) → `publicUrl(path, tenant)` using the tenant from the guard (SC5). In single mode `publicUrl(path, tenant)` returns the same env origin, so this is safe now and correct for registry mode.
7. **PER-EXPORT RULE (verbatim — B2, behavior-preserving).** Transforms apply PER-EXPORT. Where an export ALREADY calls a guard (`requireAdmin`/`requireUser`), capture `const { db } = await <thatGuard>()`. Where an export has NO guard, resolve `const { db } = await getTenantContext()` (VARIANT 2). NEVER add a `requireAdmin`/`requireUser` that is not already present — guards are behavior and this sweep is behavior-preserving. (In this batch every export is already admin-guarded, but the rule is stated so an executor never "completes the transform" by adding a guard.)
8. **Module-scope outbound-URL consts (SC5 — B1).** `admin-manual-orders.ts` has a MODULE-SCOPE `const PUBLIC_LINK_BASE = process.env.NEXT_PUBLIC_BASE_URL ?? publicOrigin();` (line 30, used to build payment links at ~:184/:196/:228/:282). Rule 6 does NOT catch this (it is not a `publicUrl(path)` call and it evaluates at module load, before any tenant exists). Move the resolution INSIDE each guarded function that builds a link and use the guard's tenant: `const base = process.env.NEXT_PUBLIC_BASE_URL ?? publicOrigin(tenant);`. Byte-identical in single mode; tenant registry domain in registry mode.

The guard return (from 24-03): `requireAdmin()` → `{ session, user, tenant, db }` (backward-compatible spread).
