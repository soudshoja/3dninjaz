<decisions_for_review>
- **D-D1 (LOCKED, flag):** Category D shared libs resolve db internally via `getTenantContext()` with an optional trailing `db?` param defaulting to the context db — NOT pure parameter-threading. Rationale: pure param-threading ripples signatures to every caller, which would break the tree between waves (violating "compiles + works after every wave"); the optional-param-default preserves request-caller signatures (zero ripple) while still letting non-request scripts pass an explicit db. This diverges from the pattern-mapper's option-1 recommendation for the truly-shared read helpers, but is the only shape compatible with the live-store compile-after-every-wave invariant.
- **W4 (clear stays sync):** `clearStoreSettingsCache` is intentionally kept SYNCHRONOUS (`map.clear()` / `map.delete(id)`) rather than made async. Making it async (to resolve tenant.id inside) would create floating-promise cache busts at the ~2 mutation call sites (the PR #39 cancellation class). Request callers pass the guard's `tenant.id` explicitly instead. Byte-identical in single mode.
- **W3 (dual-tag):** catalog's nav cache carries both the tenant-scoped tag and the bare tag transitionally to avoid an indefinitely-stale nav across the definition-side (this plan) / busting-side (24-07) wave gap, since unstable_cache has no TTL.
</decisions_for_review>
