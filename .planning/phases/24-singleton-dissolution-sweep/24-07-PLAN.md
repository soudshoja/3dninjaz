**PER-EXPORT RULE (verbatim — B2, behavior-preserving).** Transforms apply PER-EXPORT. Where an export ALREADY calls a guard (`requireAdmin`/`requireUser`), capture `const { db } = await <thatGuard>()`. Where an export has NO guard, resolve `const { db } = await getTenantContext()` (VARIANT 2). NEVER add a `requireAdmin`/`requireUser` that is not already present — guards are behavior and this sweep is behavior-preserving. This matters HERE: `custom-fonts.ts` is a MIXED file — `getActiveCustomFontsForLoader` and `listCustomFonts` are UNGUARDED public reads (the font loader renders on EVERY storefront page via `<FontFaceLoader>` in `(store)/layout.tsx`, behind a silent `catch { return null }`), while `toggleCustomFontActive`/`deleteCustomFont` are `requireAdmin`-guarded. Adding a `requireAdmin` to the unguarded loader reads would make anonymous storefront pages throw Forbidden → swallowed by the silent catch → fonts silently vanish for logged-out visitors while every gate still passes. Resolve the two unguarded reads via `getTenantContext()`; capture the guard db in the two admin exports. `products.ts`/`categories.ts`/`variants.ts` may likewise have unguarded public reads (e.g. `getProduct`/`getProducts`) alongside admin mutations — per-export, never a blanket guard.
