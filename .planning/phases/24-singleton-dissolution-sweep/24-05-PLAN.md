<interfaces>
The D-D1 transform (identical for every file in this plan), established in 24-04:
```typescript
// BEFORE (module scope): import { db } from "@/lib/db";  ... export async function foo(args) { ... db.select()... }
// AFTER: (no db value import; schema import at @/lib/db/schema stays)
import { getTenantContext } from "@/lib/tenant/context";
import type { TenantDb } from "@/lib/tenant/pool-manager";
export async function foo(args, db?: TenantDb) {
  db ??= (await getTenantContext()).db;      // request callers pass nothing; scripts pass explicit db
  ... db.select()...                          // body unchanged
}
```
Rules:
- Only the `db` VALUE import from `@/lib/db` is removed. Schema imports (`@/lib/db/schema`) stay.
- Optional `db?` is the LAST param so existing callers compile unchanged.
- For a NON-async helper that used `db`, either make it async (if callers can await) or thread db as a required param if it is only called by other Category D helpers in the same file (prefer keeping the public surface async-optional-db).
- getTenantContext short-circuits to the singleton in single mode → byte-identical.

W6 — the per-tenant-Map cache recipe for whatsapp/settings.ts (mirror 24-04 store-settings EXACTLY):
```typescript
// BEFORE: declare global { var __whatsappSettingsCache: { value; expiresAt } | null | undefined }
//         clearWhatsappSettingsCache() { global.__whatsappSettingsCache = null }   // SYNC
// AFTER:
declare global { var __whatsappSettingsCache: Map<string, { value: ...; expiresAt: number }> | undefined; }
// getWhatsappSettingsCached(db?): resolve { tenant, db } from context, key by tenant.id
// clearWhatsappSettingsCache(tenantId?: string): void   // STAYS SYNC — delete(id) or clear()
```

Pitfall-8 audit: for each file, `rg "^\s*(let|var|const) .*(cache|Cache|cached)"` and `rg "global\."` — if a module-level MUTABLE cache exists and its value is tenant-dependent (DB-derived), key it by `tenant.id` (mirror 24-04 store-settings) or convert to a per-tenant Map with a SYNC clear.
