<objective>
Add a one-click "Duplicate" action to the admin product list that deep-clones any product — regardless of productType (stocked, configurable, keychain, vending, simple) — into a new draft product, then redirects the admin to the new product's edit page.

Purpose: Admins frequently create near-identical products (same base, different colour/name/price). Cloning removes the tedious full re-entry.

Output:
- `copyProductImages()` filesystem helper (physical image directory copy + URL rewrite).
- `duplicateProduct(productId)` server action with private clone helpers for the products row, config fields, and the options/values/variants tree.
- A "Duplicate" dropdown item on each product row that calls the action and redirects to the new edit page.
</objective>

In `src/lib/storage.ts`, add `export async function copyProductImages(sourceProductId: string, destProductId: string, urls: string[]): Promise<string[]>`. Model it on `migrateNewImages` (same UPLOADS_DIR, PUBLIC_PREFIX, path-traversal guards via `path.resolve(...).startsWith(root)`, and `safeBucket` on both ids). For each URL:
  - If it does NOT start with `${PUBLIC_PREFIX}/products/${safeBucket(sourceProductId)}/`, push it unchanged (foreign/legacy URL — never rewrite blindly).
  - Otherwise extract the `<subdir>` segment after the source bucket, build `srcDir = .../products/<sourceId>/<subdir>` and `destDir = .../products/<destId>/<subdir>`, apply traversal guards, `await fs.mkdir(path.dirname(destDir), { recursive: true })`, then physically copy with `await fs.cp(srcDir, destDir, { recursive: true, force: true })` (Node 20 stable API). On success push the rewritten URL `${PUBLIC_PREFIX}/products/<destId>/<subdir>`; on any per-URL error, log and push the ORIGINAL url (never silently drop — mirrors migrateNewImages). Dedupe already-copied subdirs so the same source dir isn't copied twice.
This helper is used for product-level images, per-variant `imageUrl`, and Select-field per-option `imageUrl` alike (callers wrap single URLs in a one-element array).

In `src/actions/products.ts`, add a private `async function generateUniqueProductSlug(name: string): Promise<string>`. REUSE the existing `slugify(name)` helper for the base. Then guarantee uniqueness against the DB: `const base = slugify(name) || "product"`; query `db.select({ slug: products.slug }).from(products)` (or a `like`-filtered query on `${base}%`) into a Set; if `base` is free return it, else return `${base}-2`, `${base}-3`, ... (incrementing) until one is not in the set — matching the documented "-2/-3 on clash" slug convention. Do NOT hand-roll a different slug base algorithm; only add the clash suffix on top of `slugify`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin client -> duplicateProduct server action | Untrusted `productId` string crosses into a privileged clone operation |
| duplicateProduct -> filesystem (copyProductImages) | productId is interpolated into an on-disk path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-dw2-01 | Elevation of Privilege | duplicateProduct entry | mitigate | `await requireAdmin()` is the FIRST await before any DB/FS work (handler-level, not middleware — CVE-2025-29927). |
| T-dw2-02 | Tampering | copyProductImages path building | mitigate | Reuse migrateNewImages guards: `safeBucket()` sanitises both ids to alphanum+dash, and `path.resolve(dir).startsWith(root)` rejects any path escaping UPLOADS_DIR before fs.cp runs. |
| T-dw2-03 | Information Disclosure | cloned select-option / variant images | mitigate | Only URLs under the source product's own bucket are copied+rewritten; foreign URLs are passed through unchanged (never used to read arbitrary dirs). |
| T-dw2-04 | Tampering | slug collision on insert | mitigate | generateUniqueProductSlug checks the DB and appends -2/-3 before insert; products.slug UNIQUE constraint is the backstop. |
| T-dw2-05 | Information Disclosure | order/customer data leakage into clone | accept | Clone explicitly restricted to product-owned tables (variants/options/values/config fields); wishlists/reviews/order_items are never queried. |
</threat_model>
