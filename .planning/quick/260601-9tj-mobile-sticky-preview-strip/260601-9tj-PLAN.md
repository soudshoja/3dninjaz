# Quick Task 260601-9tj — Mobile sticky live-preview strip

## Problem

On the configurable/keychain PDP (`pancake-clicker`), the live preview sits at the
**top** of the mobile page (inside the gallery card) while the personalise form
(text input, colour chips, selects) is in the **middle**. Every edit forces the
customer to scroll **up** to see the result, then **down** to change the next
field. Type name → scroll up to check → scroll down to pick colour → scroll up
again. Desktop has no such problem (the gallery is `lg:sticky` on the side).

## Solution

Add a **mobile-only** (`lg:hidden`) sticky strip that pins a **shrunk, keychain-only**
live preview to the top of the viewport (just below the sticky site-nav) the moment
the customer starts editing. It follows them down as they fill the form, so the
preview is always visible while typing/picking colours — no scroll-up/scroll-down.

Key design facts (verified against code):
- Site-nav is `sticky top-0 z-40`, ~64px tall on mobile → strip uses `top-16` and `z-30`.
- `KeychainPreview` is a short horizontal cube row (~65–80px tall at mobile width) —
  fits an ~80–96px strip perfectly.
- `VendingPreview` is a tall 500×800 illustration — CANNOT compress into a strip,
  so the strip is gated to non-vending products (`productType !== "vending"`).
- Strip renders only when `touched` (customer has started editing), matching
  "appears once the customer starts editing".
- Existing full preview in the gallery card and all pricing/cart logic are unchanged.
