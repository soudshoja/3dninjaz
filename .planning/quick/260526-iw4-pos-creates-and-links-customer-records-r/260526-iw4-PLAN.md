<objective>
POS orders currently attribute `orders.userId` to the logged-in admin and never create a customer
`user` record. As a result the returning-customer lookup (`getPosCustomerSearch`) finds nothing, POS
customers never appear in `/admin/users`, and per-customer order history is wrong.

This plan makes `createPosOrder` resolve (find-or-create) a real customer `user` record and attribute
the order — and its coupon redemption — to that customer id, inside the existing transaction. It also
widens `getPosCustomerSearch` to match on phone (via prior orders) so phone-keyed walk-ins are findable.

Purpose: Unify POS + online customer history, make the returning-customer autofill actually fire, and
surface POS customers in the admin Customers backend.
Output: One modified file (`src/actions/admin-pos.ts`). No schema change.
</objective>
